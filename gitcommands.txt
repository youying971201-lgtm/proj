[ 日常開發提交  ]
-> 說明：當你寫好一段程式碼，想要正式存檔成為一個版本時。
1. git add <檔案名稱>                            # 將確認要存檔的檔案加入暫存區 (或用 git add . 全加)
2. git status                                   # 先確認改了哪些檔案
3. git commit -m "<請輸入這版改了什麼的說明>"      # 正式提交並寫下註解
4. git push origin <branch名稱>

[ 創造新分支 ]
-> 說明：為了不弄壞主程式，開一個獨立空間開發，開發完再合體。
1. git checkout -b <新branch名稱>               # 建立並切換到新分支開始開發
2. git checkout <新branch名稱>                  # 開發完成，切換回主分支 (main 或 master)

[ 情境 C：臨時插單切換任務 (暫存大法) ]
-> 說明：程式寫一半不能 commit，老闆卻叫你立刻切換去修另一個 Bug。
1. git stash                                    # 將目前寫到一半的進度「暫時收進抽屜」
2. git checkout <其他分支>                       # 安心切換到其他分支去修 Bug
3. ... (修完 Bug 並 commit 後) ...
4. git checkout <原本的工作分支>                  # 切換回原本正在努力的分支
5. git stash pop                                # 把抽屜裡的進度拿出來，繼續開發


[ 情境 E：與團隊的遠端雲端同步 (上下班必做) ]
-> 說明：上班時抓取最新進度，下班時把自己的進度推上雲端。
1. git pull                                     # [上班時] 下載遠端最新更新，並與本地合併
2. ... (努力工作並完成情境 A 的 commit) ...
3. git push <遠端別名> <分支名稱>                 # [下班時] 將本地最新進度推送到雲端 (例: git push origin main)

[ 情境 F：更新branch保持與main同步]
-> 說明：當你的分支開發太久，主分支已經更新了，你想把自己的基準點移到主分支最新狀態。
1. git checkout <你的開發分支>
2. git rebase main                              # 將你的分支「重新嫁接」到 main 的最前端

██████████ 第二部分：單一指令 (字典查詢) ██████████

[ 0.常用]
git status                                     ＃查看是否加入快照
git add <file full name>                       ＃把檔案加入快照
git commit -m "<簡述改動>"                       ＃設定節點『儲存點』
git pull                                        #把雲端程式拉到本地（or refresh）
git push origin <branch name>                   #把本地程式推送到雲端


[ 1. 環境設定 (只需設定一次，之後都不需要) ]
git config --global user.name "<你的姓名>"       # 設定使用者名稱 (用於追蹤作者)
git config --global user.email "<你的信箱>"      # 設定電子郵件
git config --global color.ui auto               # 自動為命令列輸出上色
git config --global core.excludesfile <檔案路徑> # 設定全域的忽略檔案清單 (如 ~/.gitignore)

[ 2. 啟動與狀態查詢指令 (Init & Inspect) ]
git init                                        # 初始化本地目前資料夾為 Git 儲存庫
git clone <遠端網址URL>                           # 複製遠端專案到本地端，並建立連接
git status                                      # 檢查工作區與暫存區的狀態 (隨時可用)

[ 3. 歷史紀錄查詢指令 (Log & Show) ]
git log                                         # 顯示目前分支的完整歷史紀錄
git log <分支A>..<分支B>                         # 查看在 B 分支但不在 A 分支的提交紀錄
git log --follow <檔案名稱>                      # 追蹤「特定檔案」的修改歷史（包含改名紀錄）
git log --stat -M                               # 顯示歷史紀錄，並標示出有移動過路徑的檔案
git show <Commit_ID>                            # 顯示「特定一次提交」的詳細變更內容

[ 4. 差異比對指令 (Diff) ]
git diff                                        # 查看所有「尚未加入暫存區」的程式碼差異
git diff <檔案名稱>                              # 查看「特定檔案」尚未加入暫存區的差異
git diff --staged                               # 查看「已加入暫存區但尚未提交」的差異
[ 5. 分支單一操作指令 (Branch) ]
git branch                                      # 列出所有本地分支，打 * 號為當前分支
git branch <新分支名稱>                          # 在目前的進度上建立新分支
git checkout <目標分支名稱>                      # 切換到指定分支
git switch <目標分支名稱>                       # 切換到指定分支
git checkout -b <新分支名稱>                     # 建立並「直接切換」到新分支

[ 6. 遠端單一操作指令 (Remote) ]
git remote add <自訂別名> <遠端網址URL>          # 新增遠端儲存庫連結 (通常別名為 origin)
git fetch <遠端別名>                             # 僅下載遠端更新的資訊，但不自動合併

[ 7. 救援與撤銷指令 (Undo - ⚠️⚠️⚠️⚠️⚠️請小心使用) ]
git reset <檔案名稱>                             # 將檔案從暫存區移回工作區（取消 add）
git checkout -- <檔案名稱>                       # 【危險】捨棄工作區中特定檔案的修改，回到上次 commit
git reset --hard <Commit_ID>                    # 【危險】強制將整個專案重置到指定版本，捨棄所有未提交修改
